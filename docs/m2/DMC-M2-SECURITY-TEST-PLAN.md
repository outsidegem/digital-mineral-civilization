## 1. Cryptographic Test Vectors (`T-VEC-*`)

| Test ID | Target | Description | Expected Result |
|---|---|---|---|
| `T-VEC-001` | `titan-identity` | RFC 8032 Section 7.1 Test Vector 1 & 2 deterministic Ed25519 sign and `verify_strict` verification. | Exact match on 32-byte public key and 64-byte signature; `verify_strict` returns `Ok(())`. |
| `T-VEC-002` | `dmc-types` | Golden byte-vector encoding and decoding for all six `DMC-CANON-V1` message types (`0x01`..`0x06`). | Exact byte-for-byte match against hardcoded hex test vectors; round-trip `decode(encode(x)) == x`. |
| `T-VEC-003` | `dmc-types` | Domain-separation header offset verification across all 6 message types. | Bytes `0..11` equal `b"DMC-SIG-V1\0"`, bytes `11..15` equal `00 01 00 01`, byte `15` equals `0x01..=0x06`, byte `16` equals `0x01`. |
| `T-VEC-004` | `titan-identity` | RFC 7914 `scrypt` known-answer vector and RFC 8439 Section 2.8.2 `ChaCha20-Poly1305` AEAD encrypt/decrypt known-answer vector (`DMC-M2-DEC-002`). | Exact 32-byte derived key, 32-byte ciphertext, and 16-byte Poly1305 tag match standard vectors. |

## 2. Invalid-Signature & Malleability Tests (`T-SIG-*`)

| Test ID | Target | Adversarial Input | Expected Rejection & Audit |
|---|---|---|---|
| `T-SIG-001` | `titan-identity` | Single-bit flip in any byte of the 17-byte `DMC-CANON-V1` header (`0..17`), payload (`17..N`), or 64-byte signature (`R` or `S`). | `Err(CryptoIdentityError::SignatureVerificationFailed)` + `SecurityFailureCode::InvalidSignature`. |
| `T-SIG-002` | `titan-identity` | Valid signature generated by registered `agent-A` (`key-A`) presented on a claim for `agent-B` or `key-B`. | `Err(CryptoIdentityError::SignatureVerificationFailed)` + `SecurityFailureCode::InvalidSignature`. |
| `T-SIG-003` | `titan-identity` | Non-canonical high-order scalar $S' = S + L$ (where $L$ is the Ed25519 group order) constructed to test signature malleability. | Rejected by `VerifyingKey::verify_strict` with `SignatureVerificationFailed` + `InvalidSignature`. |
| `T-SIG-004` | `titan-identity` | Small-order / torsion point public key (all 8 curve25519 small-order points, including `[0u8; 32]`) submitted in enrollment, rotation, recovery, or keystore load. | Rejected by `VerifyingKey::is_weak()` check with `Err(CryptoIdentityError::WeakOrInvalidPublicKey)` + `InvalidSignature`. |
| `T-SIG-005` | `titan-identity` | Cross-purpose signature replay: take a valid signature from an `AuthClaim` (`0x03`) and attach it to a `KeyRotationRecord` (`0x04`) or `KeyRevocationRecord` (`0x05`). | Rejected due to `DMC-CANON-V1` `message_type` domain separation (`SignatureVerificationFailed` + `InvalidSignature`). |

## 3. Challenge, Expiry & Replay Protection Tests (`T-AUTH-*`)

| Test ID | Target | Scenario | Expected Rejection & Audit |
|---|---|---|---|
| `T-AUTH-001` | `titan-identity` | Valid fresh challenge signed by active enrolled key within 5-minute TTL. | `Ok((ResolvedAgentIdentity, SecurityAuditRecord))` with `IdentityTrustStatus::CryptographicallyVerified`; challenge marked `Consumed`. |
| `T-AUTH-002` | `titan-identity` | Replay attack: submit the exact same valid `SignedIdentityClaim` a second time. | `Err(CryptoIdentityError::ChallengeError(ChallengeError::ChallengeReplayed(_)))` + `SecurityFailureCode::ReplayAttempt`. |
| `T-AUTH-003` | `titan-identity` | Challenge ID exists and is unconsumed, but caller substitutes a different 32-byte `nonce` or different `target_agent_id`. | `Err(NonceMismatch / TargetAgentMismatch)` + `SecurityFailureCode::ReplayAttempt`. |
| `T-AUTH-004` | `titan-identity` | Challenge lifetime requested at issuance exceeds `MAX_CHALLENGE_TTL_MS` (`300_001 ms`). | Issuance fails closed with `ChallengeError::TtlExceedsMaximum` before storing challenge. |
| `T-AUTH-005` | `titan-identity` | Expired wall-clock timestamp (`eval_epoch_ms >= expires_at_epoch_ms`). | `Err(ChallengeError::ChallengeExpired)` + `SecurityFailureCode::ReplayAttempt`. |
| `T-AUTH-006` | `titan-identity` | Monotonic clock elapsed duration exceeds `max_ttl` even when caller passes a manipulated/stalled `eval_epoch_ms`. | `Err(ChallengeError::ChallengeMonotonicTtlElapsed)` + `SecurityFailureCode::ReplayAttempt`. |
| `T-AUTH-007` | `titan-identity` | Future-dated challenge (`eval_epoch_ms < issued_at_epoch_ms`). | `Err(ChallengeError::FutureDatedChallenge)` + `SecurityFailureCode::ReplayAttempt`. |
| `T-AUTH-008` | `titan-identity` | Replay cache saturation: issue `MAX_ACTIVE_CHALLENGES` (`10,000`) unexpired challenges, then attempt to issue challenge `10,001`. | Fails closed with `ChallengeError::ReplayCacheSaturated`; none of the `10,000` unexpired challenges are evicted. |
| `T-AUTH-009` | `titan-identity` | Verifier restart simulation: issue challenge on `registry_v1`, instantiate `registry_v2` (simulating process restart with same `registry_id`), and present claim signed for `registry_v1`. | Rejected with `ForeignRegistryInstance` / `UnknownOrRestartInvalidatedChallenge` + `ReplayAttempt`. |
| `T-AUTH-010` | `titan-identity` | Claim requests `claimed_autonomy` higher than agent's enrolled `max_autonomy` or requests `E5ReservedAuthority`. | Rejected with `AutonomyClaimExceedsRegistered` / `ReservedAuthorityNotResolvable`. |

## 4. Development Keystore, `scrypt` & `ChaCha20-Poly1305` Tests (`T-KS-*` — `DMC-M2-DEC-002`)

| Test ID | Target | Scenario | Expected Result & Security Enforcement |
|---|---|---|---|
| `T-KS-001` | `titan-identity` | Generate `DevSigningKey`, save to `0700` dir outside Git workspace with baseline `scrypt` (`log_n = 15, r = 8, p = 1`) and `ChaCha20-Poly1305`, and reload with correct `SecretPassphrase`. | Key file created with mode `0600`; round-trip public key and signing behavior match; `custody_assurance == LocalDevelopmentOnly`. |
| `T-KS-002` | `titan-identity` | Save the same `DevSigningKey` twice with the same passphrase and compare raw `.dmcks` file bytes. | Both `kdf_salt` (`bytes[48..80]`) and `aead_nonce` (`bytes[80..92]`) and `encrypted_seed` differ completely between saves (unique CSPRNG salt and nonce per write). |
| `T-KS-003` | `titan-identity` | Attempt `load_key` with an incorrect passphrase (1 byte changed). | Fails closed with `KeystoreError::AuthenticationFailed` + `SecurityFailureCode::KeystorePermissionViolation`. |
| `T-KS-004` | `titan-identity` | Flip 1 bit in any AAD field (`ks_version`, `custody_tag`, `scrypt_log_n`, `agent_id`, `key_id`, or `public_key`), or in `encrypted_seed`, or in `poly1305_tag`. | Fails closed at Poly1305 verification (`KeystoreError::AuthenticationFailed`) or pre-KDF header check (`InvalidKeystoreEnvelope`). |
| `T-KS-005` | `titan-identity` | Validate `ScryptParamsConfig::new_checked` across the full valid grid `log_n in 15..=16`, `r in 8..=15`, `p in 1..=2` and verify `working_memory_bytes() == 128 * r * ((1 << log_n) + p + 1) <= 134_217_728` and `work_factor() == (1 << log_n) * r * p <= 1_966_080`. | Every configuration inside the derived bounds succeeds (`Ok`) and stays strictly within the `128 MiB` heap ceiling and `1,966,080` CPU work-factor cap. |
| `T-KS-006` | `titan-identity` | Present oversized keystore file (`1025` bytes > `MAX_KEYSTORE_FILE_BYTES`) or truncated file (`100` bytes < `183` bytes) or file with 1 trailing byte. | Rejected before KDF execution with `FileSizeOutOfBounds` / `InvalidKeystoreEnvelope`. |
| `T-KS-007` | `titan-identity` | Create keystore directory inside the Git workspace or with permissions `0755`, or key file with permissions `0644`, or symlink key file. | Rejected before KDF execution with `PathInsideGitWorkspace` / `InsecurePermissions` / `SymlinkNotAllowed`. |
| `T-KS-008` | `titan-identity` | Passphrase shorter than `12` bytes, longer than `256` bytes, or all whitespace. | Rejected before KDF execution with `KeystoreError::InvalidPassphraseLength`. |
| `T-KS-009` | `titan-identity` | Encrypt an Ed25519 seed whose derived public key does not match the AAD `public_key` field (using a valid Poly1305 tag computed with the mismatched AAD). | Rejected after AEAD decryption by the post-decryption public-key correspondence check (`KeystoreError::DecodedPublicKeyMismatch`), zeroizing the seed. |
| `T-KS-010` | `titan-identity` | Unsupported `ks_version = 2`, `kdf_id = 0x02`, or `aead_id = 0x02`. | Rejected before KDF execution with `UnsupportedKeystoreVersion` / `UnsupportedKdfOrAead`. |
| `T-KS-011` | `titan-identity` | Verify `SecretPassphrase` and `DevSigningKey` `Debug` and `Display` formatting and zeroization on drop. | Output is strictly `"<REDACTED-PASSPHRASE>"` and `"<REDACTED-DEV-SIGNING-KEY>"`; raw seed bytes never appear in memory dumps or logs. |
| `T-KS-012` | `titan-identity` | Confirm no API or fallback writes plaintext private keys when encryption or CSPRNG fails. | Simulated failure leaves zero `.dmcks` or `.tmp` files on disk (`PlaintextFallbackProhibited`). |
| `T-KS-013` | `titan-identity` | **Maximum Accepted Memory Configuration (`DMC-M2-AUDIT-004`):** Construct `ScryptParamsConfig::max_accepted()` (`log_n = 16, r = 15, p = 2`) and standard-`r` max (`log_n = 16, r = 8, p = 2`); verify exact heap bytes and round-trip save/load. | `Ok(ScryptParamsConfig)`: for `(16, 15, 2)`, `working_memory_bytes() == 125_834_880` (`|V| = 125_829_120` + `|B| = 3_840` + `|T| = 1_920` $\le 134_217_728$), `work_factor() == 1_966_080`; for `(16, 8, 2)`, `working_memory_bytes() == 67_111_936`. |
| `T-KS-014` | `titan-identity` | **First Rejected Configuration Above Memory Ceiling (`DMC-M2-AUDIT-004`):** Test `(log_n = 16, r = 16, p = 1)` (`total_heap_bytes = 134_221_824 = 128 MiB + 4_096 B`) and `(log_n = 17, r = 8, p = 1)` (`total_heap_bytes = 134_219_776 = 128 MiB + 2_048 B`). | Both fail closed with `Err(KeystoreError::KdfParametersOutOfBounds)` (`computed_mem_bytes: Some(134_221_824)` and `Some(134_219_776)` exceeding `MAX_KDF_MEMORY_BYTES = 134_217_728`). |
| `T-KS-015` | `titan-identity` | **Integer Overflow & Invalid Parameter Handling (`DMC-M2-AUDIT-004`):** Test `log_n in [0, 14, 64, 255]`, `r in [0, 7, u32::MAX]`, `p in [0, u32::MAX]`, and `(log_n = 63, r = u32::MAX, p = u32::MAX)`. | Checked arithmetic (`checked_shl`, `checked_mul`, `checked_add`) catches all overflows and under-bounds without panic, returning `Err(KeystoreError::KdfParametersOutOfBounds { computed_mem_bytes: None, .. })`. |
| `T-KS-016` | `titan-identity` | **Rejection Before KDF Allocation (`DMC-M2-AUDIT-004`):** Pass a `.dmcks` file header containing `log_n = 17, r = 16, p = 4` (`268_445_696 B` $\approx 256\text{ MiB}$) or `log_n = 22, r = 8, p = 1` (`536_872_960 B` $\approx 512\text{ MiB}$) to `DevKeystore::load_key`. | Rejected during pre-KDF header validation in `< 1 ms` with zero allocation of `scrypt` `v`/`b`/`t` buffers (`KeystoreError::KdfParametersOutOfBounds` + `SecurityFailureCode::KeystorePermissionViolation`). |
| `T-KS-017` | `titan-identity` | **Excessive CPU-Cost Parameters (`DMC-M2-AUDIT-004`):** Test `(log_n = 16, r = 8, p = 16)` (where `total_heap_bytes = 67_126_272 B <= 128 MiB`, but `p = 16 > MAX_SCRYPT_P (2)` and `work_factor = 8_388_608 > MAX_KDF_WORK_FACTOR (1_966_080)`) and `(log_n = 16, r = 15, p = 3)` (`work_factor = 2_949_120 > 1_966_080`). | Rejected before KDF allocation with `Err(KeystoreError::KdfParametersOutOfBounds)` + `SecurityFailureCode::KeystorePermissionViolation`, preventing single-threaded CPU exhaustion even when memory is below `128 MiB`. |

## 5. Key Lifecycle & Rotation Tests (`T-ENROLL-*`, `T-ROT-*`)

| Test ID | Target | Scenario | Expected Result |
|---|---|---|---|
| `T-ENROLL-001` | `titan-identity` | Enroll agent with valid `ActiveEnrollmentAndRecovery` Founder Root signature. | `Ok(_)`; `registry_sequence` increments from `0` to `1`; key status is `Active`. |
| `T-ENROLL-002` | `titan-identity` | Attempt enrollment signed by `EmergencyRecoveryOnly` root key, unknown root key, or routine agent key. | Rejected with `InvalidRootRole` / `UnknownOrRevokedRootAnchor` + `SecurityFailureCode::RootTrustFailure`; `registry_sequence` unchanged. |
| `T-ROT-001` | `titan-identity` | Immediate-cutover rotation signed by `old_key_id` (`Active`) and `new_key_id` (PoP). | `Ok(_)`; `AgentId` unchanged; `old_key_id` becomes `Retired`; `new_key_id` becomes `Active`; `registry_sequence` increments. |
| `T-ROT-002` | `titan-identity` | Attempt to authenticate or sign a second rotation using `old_key_id` immediately after `T-ROT-001` (zero-overlap verification). | Rejected with `KeyNotActive { status: Retired { .. } }` + `SecurityFailureCode::RevokedCredential` / `InvalidRotation`. |
| `T-ROT-003` | `titan-identity` | Rotation with valid `old_key_signature` but missing/invalid `new_key_pop_signature`. | Rejected with `SignatureVerificationFailed` + `SecurityFailureCode::InvalidRotation`; `old_key_id` remains `Active`. |
| `T-ROT-004` | `titan-identity` | Rotation attempting to reuse the same 32-byte public key or an existing `KeyId`. | Rejected with `IdenticalRotationKeyMaterial` / `DuplicateKeyId` + `SecurityFailureCode::InvalidRotation`. |
